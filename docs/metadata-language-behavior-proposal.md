# 名称の言語選択と表示安定性：仕様見直し案

2026-09-20。**作成時点は相談用の提案。以下に提案時の問題整理と条件を残す。**
ユーザーの「漏れや不具合が多いので仕様を改めて決めるべきではないか」を受け、追加実装を止めて整理した。その後、この文書に取り組む依頼と英語表記関連資料を確認する依頼を受け、以下の表示規則を基準に実装へ進んでいる。
現在の設計・関連資料の照合・確認状況は[着手後の作業記録](verification/records/2026-09-20-metadata-language-behavior.md)と[仕様整理](metadata-language-spec.md)を参照する。着手やコードの存在を、全条件の合格として扱わない。
既存の取得方法・閾値・キャッシュ構造をユーザー要件として固定しない。

## 現状の判断

今回発見した取得漏れと再評価中のちらつきを直すだけで、問題全体を解消したとは判断できない。
前回の3曲での成功は、同じアルバム全曲・初回読込・再取得中・再起動を通した合格ではなかった。
以後は画面で満たすべき条件を先に決め、取得、判定、保存、表示の各段をその条件へ合わせる。

## 維持する既存の合意

- 英語とコンテンツ言語の名称を別々に取得・保持し、両方で検索できるようにする。
- 設定OFFはコンテンツ言語を優先する。ONは正式な原表記が英語と判断できる名称を英語で表示する。
- 国籍、歌唱言語、Latin文字、一曲の判定だけから、人物・アルバム・全収録曲の言語を決めない。
- 手動名と端末内タグを保護する。表示変更で再生ID、保存曲、曲順、人物との関係、再生位置を変えない。
- 未確認の英語候補を、確認済みの原題として扱わない。

根拠と従来実装は [現在の仕様資料](metadata-language-spec.md) を参照する。

## 今回明確にする表示規則（提案）

| 状態・操作 | 期待する表示 |
| --- | --- |
| 確認済みの英語原題、設定ON | 原題と一致する英語表記。動画用の付記が付いた詳細名だけを優先しない。 |
| 原題が英語以外、または初回の確認で不明・競合 | コンテンツ言語の名称。英語を自動生成しない。 |
| 既に確認済みの名称を再取得・再評価中 | 最後に確定した表示を維持する。処理途中という理由で日本語へ戻さない。 |
| 取得失敗・通信切断 | 保存済みの確定表示を維持し、再試行する。失敗を「原題は日本語」と同一視しない。 |
| 新しい確認結果が原題の変更、別言語、根拠の撤回、競合を示す | 新しい判定が完成した時点で表示を更新する。古い英語表示を無期限に正解扱いしない。 |
| 設定ON/OFF・コンテンツ言語変更 | 共通の選択結果を一度更新し、表示中の各画面へ同じ状態を反映する。再取得完了を待って戻したりしない。 |
| 保存済みデータでのアプリ起動・画面再訪 | 保存済みの確定表示から開始する。「英語→日本語→英語」を挟まない。 |
| 初めて取得する曲 | 取得前は共通のコンテンツ言語表記を基準とし、原題確認完了による一度の切替は許容する。今回の実装はこの境界を採用する。 |

「再評価待ち」「初回の原題不明」「再評価が完了して不明」「取得失敗」を別の状態として扱う。
取得中に名称候補だけ更新した状態と、古い判定を組み合わせて画面へ公開しない。
再評価不能時にも、確認済み結果の取得時点と根拠を保持し、根拠の明示的な撤回とは区別する。

## アルバム内の曲を漏らさない条件（提案）

- 同じアルバムの全収録曲を対象に、各曲の原題とその言語を確認する。一部の曲の成功でアルバムを完了にしない。
- 音源用IDと通常のアルバム一覧のIDが異なる場合も対象とする。配信元が提供する安定した項目IDによる対応を使い、名前や順番の一致だけで曲を統合しない。
- 対応の証拠、原題の証拠、原題の言語判定を区別して保存する。動画種別が特定の型かどうかを、その曲を原題確認の対象にする唯一の条件にしない。
- 同一アルバムでも多言語の作品は曲ごとの判断を維持する。短い題名にアルバム文脈を使う場合も、別曲の名前を流用しない。
- 取得できない曲が残れば、そのアルバムは確認未完了として残す。画面が表示できたことを、原題確認の完了と混同しない。

今回の調査では、Nevermindの同一プレイリストに対する2種類のMusic応答で、13曲すべてが同じ`playlistSetVideoId`によって対応した。
これは新たな実装候補の根拠であり、対応経路の実装完了・一般作品での安全性・画面改善を証明するものではない。

## 完了条件（提案）

| 確認軸 | 合格の条件 |
| --- | --- |
| 対象作品 | Nevermind全13曲、別の英語作品、英語名を含む日本語作品、多言語・短い題名・別版を含む作品で期待値を事前に決める。 |
| 対象画面 | 検索、通常のアルバム全曲一覧、ライブラリ、プレイヤーで、同じ対象IDの表示が一致する。 |
| 設定 | ON/OFF、コンテンツ言語変更が全対象へ反映される。UI言語だけの変更と混同しない。 |
| 時間 | 初回、再訪、完全終了後、期限切れの再取得、別アルバム情報の追加中を確認する。最終画面だけでなく表示の時系列も記録する。 |
| 失敗 | 空応答、部分取得、遅延、通信失敗、再試行、古い要求の遅着で、確定表示の消失や繰り返し切替がない。 |
| 更新 | 本当に原題や関連が変わった場合は新しい確定結果へ移り、古い表示を保持し続けない。 |
| データ保護 | 既存の曲ID・曲順・raw名称・関連・キュー・再生位置、手動名・ローカルタグを保つ。 |
| 成果物 | 最終差分のテストと、渡すrelease APKでの対象画面確認を区別して記録する。release通信の既知制約は別記する。 |

既知の失敗が残るケースを「PASS」「全体完了」と呼ばない。
この条件を満たしても未発見の不具合が絶対にゼロであるとは断言せず、何を確認できたかを具体的に示す。

## 実装の進め方

提案時は、まず表示規則と上記の完了条件を確認し、次に状態遷移と証拠の取得・無効化を設計する方針だった。着手の依頼を受け、現在は確認対象の期待値と失敗時のテストを用意しながら、次の分離を実装している。

- 取得途中の原情報と、評価が完成した表示結果を分ける。DB29へ具体的な英語表示名と根拠を保存し、評価・採用名を一度に確定する。待機や失敗では前の確定結果を使い、完成した不明・競合・撤回は更新する。
- 保存済み名称と確定結果の最初のDB読込が済んでから通常画面を表示する。通信や初回の原題評価は初期画面の待機条件にしない。
- 正規アルバムの同じplaylist ID内で`playlistSetVideoId`を照合する経路を加える。対応の証拠だけで原題・原言語を認定せず、直接原題と取得済み英語候補と評価を別々に確認する。browse/nextのcontinuationは発行済みtokenだけを追跡し、全ページの安定項目集合が一致するまで成功として公開しない。重複・ループ・別playlist・途中失敗は確認未完了として保持する（100ページ・10,000項目の実装上限あり）。

停止時に保管した書きかけの草案は、承認済み仕様や検証済み実装として復元しない。今回の設計との整合、最終差分のテスト、エミュレータ通常操作、配布するreleaseの確認を分け、結果は作業記録へ集約する。既知の未確認や不合格を残したまま全体完了としない。
