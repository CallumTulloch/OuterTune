# 初回ホーム取得と導入案内の配置

## 対象・合格条件

- 前回のアルバム単位アーティスト集約を `475e6aa9` にコミット後、今回の依頼へ着手。
- ユーザー報告：インストール直後のホーム情報取得が初回に失敗する。
- 初回の匿名訪問者情報がホーム通信の途中で届いても、古い要求を破棄して新しい状態で取得し直し、再試行操作を要求しないこと。
- 通常の通信失敗・タイムアウトを無制限に再試行しないこと。言語・認証変更時に以前のページ、チップ、継続トークン、アカウント依存の推薦を引き継がないこと。
- 「バックアップがある」「スキップ」の配置をfork共通祖先のものへ戻す。クリック処理・同期無効化の仕様は保持。
- 検証中に見つかった関連不具合：案内中のアプリ言語変更によるActivity再生成後、スキップしてもホームへ戻れず空白画面になる。復元済みの案内を重複追加せず、バックアップ画面の復元も維持すること。
- 追加のユーザー指示：検証PCの既知の証明書エラーを毎回調査しないよう、着手時に読む資料へ記録する。

## 原因・変更

- `AuthenticationRepository.start()` は保存済みの認証を同期反映後、未保存の訪問者情報を非同期取得する。完了すると `authRevision` が増える。
- `InnerTube.browse()` は途中で認証が変わった応答を `AuthenticationChangedException` で拒否する。ところが `HomeViewModel` はコンテンツ言語だけを監視し、`HomeFeedLoader` はこの失敗を手動再試行待ちとしていた。この初回限定の競合は `67e69d4d` で導入された処理の組合せで説明できる。
- コンテンツ言語と保存済みの認証はアプリ起動時に同期反映される。今回の競合はその読み込み前に画面が起動するものではなく、初回だけ未保存の訪問者情報が後から届く順序で発生する。保存済み訪問者情報がある起動では、この追加の認証世代変更はない。
- ホームが言語と認証世代の両方を監視し、変更時は進行中のホーム・推薦取得を取り消し、最初のページから取得し直す。古い認証の応答を拒否する仕組みと通常の通信エラーの手動再試行は保持。
- オンラインの表示状態の反映はメインスレッドへ集め、更新番号・現在の言語・認証世代を確認してから行う。古いIO処理の完了が、変更時に消したアカウント情報・推薦・Exploreを再表示しないようにする。読み込みフラグの開始もメインスレッドの更新開始処理へ移し、終了処理は現在の更新番号の場合だけ反映する。
- 配置の変更元は `ed94703d`、fork共通祖先は `12f61da0`。対象の `FlowRow` と開始16dp/終了64dpを、元の `Row` と左右48dpへ戻した。
- `SetupWizard.kt` の共通祖先369～397行と今回343～371行の対象ブロックは一致する。左右への配置、余白だけでなく、バックアップ画面への移動とスキップ時の案内完了処理も同じである。今回の変更範囲で同期機能やログイン機能の仕様は変えない。
- `MainActivity` は起動時に案内が未完了なら無条件で `setup_wizard` を追加していた。Activity再生成時には既にナビゲーション履歴が復元されるため、案内が二重になり、スキップの `navigateUp()` 後も完了済み案内が残る。完了済み状態に対応する案内ページはなく、内容が空白になっていた。`openSetupIfNeeded()` で履歴内の案内の存在を確認し、未追加のときだけ開く。スキップ・完了処理は変更しない。
- この重複追加と単一の `navigateUp()` の組合せはfork以前から存在しており、今回戻したボタンの余白とは別の不具合。
- `AGENTS.md` と `docs/development-workflow.md` に、既知の検証PCの証明書エラー、反復確認を行わない条件、代替の確認方法、再調査する条件を記載した。製品APKの証明書検証や信頼設定は変更しない。

## 検証

DB27を維持し、今回の変更に追加のDB初期化はない。実端末・ユーザーの認証情報は使用しない。

### 再現状況と検証方法

- **OBSERVED／修正前**：前回のcoreDebug APKを初期状態で起動し、案内をスキップした通常通信の1試行では、ホームは取得できた。`build/diagnostics/home-startup-20260913/01-baseline-setup.*`、`02-baseline-home.*` に画面と階層を保存。ユーザーの実端末で「初回に必ず失敗する」という現象そのものは、この試行では再現していない。
- 実行順序に依存するため、`HomeStartupTest` では実ViewModel・メモリ内Roomを使用し、ホーム要求中に訪問者情報取得相当の認証世代を変更する順序を固定した。通常の通信環境で偶然成功することを、競合がない根拠にはしていない。
- テストの外部応答は合成データ。遅れて失敗する旧要求と、キャンセルを無視して成功する旧応答の両方を使用する。旧処理の終了を待ってから、表示の巻き戻り・エラーの残留がないことを確認する。

#### 画面の証跡と制約

- 検証対象は `Pixel_9_API_35` / `emulator-5556`。今回起動した一時エミュレータだけを使用し、アプリのデータ初期化もこの環境に限定した。
- 検証後に画面密度とWi-Fi・データ通信を元へ戻し、今回起動したプロセスのAVD・ポート・IDを照合して終了した。ADBの接続一覧が空であることを確認し、エミュレータの操作担当を解除した。
- 証跡保存先：`build/diagnostics/home-startup-20260913/`。PNGとXMLを保存。
- **OBSERVED／途中版**：`06-debug-home-ja.*`、`11-release-first-home.*`、`12-release-first-home-settled.*` はActivity再生成後のスキップで、下部ナビゲーション以外が空白になる修正前の状態。Homeを選び直すと戻ること、再生成なしの初回スキップでは空白にならないことも確認した。
- **PASS／最終版**：`16`～`19-navfix-debug-first-home.*` はdebugの初回案内・日本語への再生成・バックアップ・ホーム取得成功。`20`～`26-navfix-release-restarted-home.*` はreleaseのオフライン案内・復元・スキップ・再起動。配布APKでの日本語ボタン配置は `21-navfix-release-recreated-ja.png`。
