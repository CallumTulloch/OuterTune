# アーティスト内部画面の選択元の曲欄を削除

対象HEAD: `4def7ed10c8862e17c1e2948a4fc17c57d84510e`＋既存および本改修の未コミット差分。ブランチ`restart/artist-20260905`。

## 現象・合意した動作

- アーティストのローカル表示へ切り替えると、再生も保存もしていない曲が「Songs opened from／このアーティストを選択した曲」に多数並ぶ。
- ユーザーはこの追加欄の削除を確定し、その方針で実装するよう指示した。移設や履歴への転用はしない。
- 保存済みの曲は従来の3曲プレビューと全曲への入口を維持する。情報補完で一時的に取得した未保存曲を、ローカル側のシャッフルへ混ぜない。
- 根拠と修正前の実機再現は[調査記録](2026-09-07-artist-source-songs-investigation.md)を参照する。

## 変更

- `ArtistScreen.kt`から追加欄の見出し・全曲行・行を選択した際の再生処理を削除した。
- 内部ページのシャッフルは`librarySongs`だけから再生対象を作る。`ArtistContext.sourceSongs`への依存をこの画面から取り除いた。
- `librarySongs`は既存の`artistSongsPreview`を引き続き使う。対象はライブラリ登録済み・ダウンロード済み・ローカル音源のいずれかで、プレビューは最大3曲。今回シャッフルを全曲へ拡張する変更は含めない。
- 人物名、オンラインIDの補完、IDなし人物の内部ページ、保存済み曲とアルバムの表示、現在表示中の種別を示すアイコンは維持した。DB・情報補完リポジトリは変更していない。

## 確認

- コード確認: `ArtistScreen.kt`に`sourceSongs`／`artist_source_songs`／`internalSongs`の参照は残っていない。シャッフル用キューは既存の保存曲プレビューのみを入力とする。追加欄専用の未使用importを削除した。
- 未実施: 最終ソースのビルドおよび端末確認は検索改修と合わせて担当エージェントが行う。本記録の時点で画面動作をPASSとはしていない。

端末での合格条件:

1. 未保存・未再生の検索結果からアーティストを開き、オンライン表示を経てローカルへ切り替えても追加欄が出ない。保存曲が0件ならローカル側のシャッフルは無効になる。
2. 保存済み曲がある人物では通常の曲欄を表示し、最大3曲と全曲への入口を保つ。シャッフルに閲覧しただけの未保存曲が入らない。
3. IDなし人物の内部ページで名前を表示でき、通常の人物ページへの移動と現在表示中の種別アイコンを保つ。
