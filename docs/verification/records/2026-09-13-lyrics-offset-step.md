# 歌詞タイミング調整を0.2秒刻みにする

## 課題・範囲

- 現象：プレイヤーの歌詞表示中に開ける「歌詞のタイミング調整」の「早める」「遅らせる」が1回ごとに0.5秒変化する。
- 期待：1回ごとに0.2秒変化する。保存済みの曲別調整値、±30秒の範囲、リセットを維持する。
- 根拠：`Player.kt` の `ActionButtons` にある2個のボタンだけが調整量を指定している。`Lyrics.kt` は保存されたミリ秒を追跡位置と歌詞タップ位置へ適用する。
- DB、歌詞の取得・解析、追跡更新頻度、ほかの再生設定は変更しない。

## 実装

`Player.kt` の2個のボタンを `-500L` / `+500L` から `-200L` / `+200L` に変更した。
曲別の保存は従来どおり整数ミリ秒の `Long` なので、加減算の浮動小数点誤差は発生しない。表示も小数1桁の秒数を維持する。
既存の0.5秒などの値を0.2秒の倍数に丸めない。たとえば保存済みの+0.5秒はそのまま読み込み、次の操作で+0.3秒または+0.7秒になる。上下限で超えた分だけ従来どおり±30秒へ制限する。

## 合格条件・画面確認手順

1. 曲を再生してプレイヤーを開き、歌詞表示に切り替える。
2. お気に入りの隣に出る左右矢印のボタンから「歌詞のタイミング調整」を開く。
3. リセット後に「遅らせる」を押すと+0.2秒、もう1回で+0.4秒。「早める」を押すと+0.2秒へ戻る。
4. メニューを閉じて開き直しても値が維持され、リセットで+0.0秒になる。
5. 保存済みの+0.5秒から操作すると+0.7秒/+0.3秒となり、勝手な丸めを行わない。

## 確認状況

- ソース確認済み：調整ボタンは上記2箇所のみ。保存形式、±30秒の制限、リセット、追跡・歌詞タップへの適用は変更なし。
- 単純な定数変更をなぞる単体テストは追加しない。
- 最終ソースのビルド・実画面確認：親担当の統合検証待ち。ここではGradle・ADBを実行していない。
