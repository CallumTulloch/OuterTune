# 検索結果の種別表示と再生アニメーション

2026-09-07。開始HEAD `a80f2615`、ブランチ `restart/artist-20260905`。
既存のアーティスト改修を含む未コミット作業ツリーに追加する変更。

## 現象と合意した仕様

- 検索結果に再生中の曲とそのアルバムが並ぶと、同じ表紙と異なる動きの再生表示により、別々の曲が再生されているように見える。
- ユーザーが承認した表示案は、48dpの角丸表紙と、種別・再生状態／タイトル／アーティストなどの3段表示。行は通常84dp程度、角丸のアクティブ背景を使用する。
- 追加のユーザー条件により、3段表示は検索フィルター「すべて」に限定する。個別フィルター、検索候補、ライブラリ等は従来表示を維持する。
- 曲は「曲」「再生中／一時停止中」、アルバムは「アルバム」「収録曲を再生中／収録曲を一時停止中」。再生対象でない項目も種別を表示する。
- 現在の曲IDと一致する曲、その曲のアルバムIDと一致するアルバムだけをアクティブにする。アルバムをタップする操作はアルバム画面への移動を維持する。
- 同じ検索画面の再生表示は共通の描画時刻から同じ波形を描く。後から画面内に入った行も同期し、一時停止中は動かさない。

## 合格条件

1. 「すべて」では同じ表紙・同じタイトルの曲とアルバムを文字で区別できる。アーティスト情報の表示処理、メニュー、曲再生とアルバム遷移を維持する。
2. 非アクティブ、再生中、一時停止中の表示が正しく、個別フィルターでは種別行を追加しない。
3. 同時表示、スクロール等による遅い参加、停止・再開後の再生アニメーションが同期する。
4. 対象ソースのコンパイルと、実コンポーネントの表示・状態確認を行う。APKを生成する場合はcore / arm64-v8aのみ。

## 実装・検証

- `OnlineSearchResult` が「すべて」だけ `showSearchMetadata` を有効にし、検索リスト全体に一つの再生描画時刻を供給する。
- `SearchResultListItem` は既存のアーティスト表記・時間・年・バッジを受け取り、新しい種別・状態行を追加する。長い文字は折り返す。一時停止アイコンはこの新表示だけpauseを使い、他の行は従来のアイコンを維持する。
- `PlayingIndicator` は共有時刻をCanvas内で参照する。毎フレーム検索リストを再構築せず、停止時・画面終了時は時計更新を停止する。OSのアニメーション倍率の変更も監視する。他画面の既存アニメーションは変更しない。
- 検索パーサーが元のWatchEndpointを保持する。ATVは「曲」、OMV/UGCは「動画」、情報なし・未知値は「曲・動画」とし、タイトルや時間から推定しない。
- debug専用の空Activityで実コンポーネントを表示する。検索・再生・画像取得の成功に依存せず表示を検査でき、本番releaseに検証Activityは含めない。

最初の検索パーサーテストは37件中1件失敗。アルバム用の行fixtureは親アルバムの画像を使うため行自体に画像がなく、検索パーサーの必須条件でnullになったことが原因。保存済みの実検索行へ差し替え、製品コードの必須条件は緩めていない。
