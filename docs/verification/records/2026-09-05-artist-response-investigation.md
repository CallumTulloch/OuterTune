## 2. 正常例と、記号が正式名に含まれる例

### 二人の名前が別々に届く例

Lady Gaga / Bruno Mars「Die With A Smile」を次の二つの収録版で確認した。

- 単曲版：`RVDCeVG90Rg`、アルバム `MPREb_awgUw0NYaZA`。
- MAYHEM収録版：`DlFXDl_ROAM`、アルバム `MPREb_fdn3rDTkRH3`。

両方のキューで、次のように同じ二つのIDが別々の名前Runに付く。

```text
Run 0: レディー・ガガ → UCGKXb1syicud01CJOOFRykg
Run 1: 、            → IDなし（独立した区切り）
Run 2: ブルーノ・マーズ → UCZn4r7heNOPY-C43YIywnVA
```

どちらのIDも実ページを取得して名前を確認済み。検索「曲」でも両名が別Runで返る。
なお、単曲版のアルバム見出しには両名があるが、MAYHEMのアルバム見出しはLady Gaga一名。MAYHEMの対象曲行には両名がある。
**アルバムの人物一覧をそのまま曲の人物一覧にする仕様は、この正常例でもBruno Marsを落とす。**

### カンマとアンパサンドを含む一組

Earth, Wind & Fire「September」の2収録版を確認した。

- `OBM0DO8Xt1c`：アルバム `September (sped up + slowed)`。
- `B2mmDEv0OEk`：アルバム `Feel Good Friday`。

日本語指定では両方とも `EARTH,WIND & FIRE` の一つのRunに `UCdyqvgHHq9NEEfV20lO61jQ` が付く。
英語指定では `Earth, Wind & Fire` と表示され、IDは同一。アーティストページ取得でも名前を確認済み。
カンマと `&` を分割すれば、一組を誤って複数人として扱う。この例では、Runの中身を分割しない現在のオンライン処理が名前を保持する。

## 3. 同じIDが別のアルバムで結合名に付くか

**今回のサンプルでは、正しく分かれた名前と、複数名を結合した名前の両方のRunに同じIDが直接付く実例は見つからなかった。**
全サービスで起こらないとは断定できない。

追加比較は10アルバム（8082Audio関連8件、デュエット2件）を含む13応答。
おすすめを含むアーティスト型のRun160件・ID49種類を比較した。複数の名前表記が見つかった3種類のIDは英語／日本語の表記差で、結合名の誤関連付けを示すものではなかった。

上記の8082AudioのIDはすべて `UChWKQRswWTLRXp98zmgHtdQ`。サウンドトラックの曲は元の対象曲と異なる動画IDなので混同しない。
その曲と伴奏 `yq0Dzo3jJ10` をgetQueueでも取得し、結合名・IDなしを確認した。

また、同一IDに別の正常表記が付く例はある。単曲版の見出しの `ブルーノ・マーズ` と、別アルバム `Leave The Door Open (Live)` のおすすめカードの `Bruno Mars` は同じID。
したがって、名前の単純な完全一致を要求すると、正しい翻訳・表記差まで不一致と判断する可能性がある。

YouTubeの[入稿仕様](https://support.google.com/youtube/answer/12029076?hl=en-EN)も、複数アーティスト、役割、名前、識別子、翻訳を別の情報として扱う。
ただし、これは配信元がYouTubeへ送る情報の仕様であり、アプリが使うInnertubeのRunに必ず同じ粒度で返る保証ではない。
[公式の修正案内](https://support.google.com/youtube/answer/6082427?hl=en)では、アーティストチャンネルとの誤関連付けと、主アーティスト・客演情報の誤りも区別されている。

## 4. 外部IDがない場合の方針案

以下は調査に基づく提案であり、まだ実装・仕様確定はしていない。

| 確認できた情報 | 提案する扱い |
| --- | --- |
| 個別名とその曲との関係が確認でき、外部IDも対応する | 個別Artistとして登録し、内部の関連曲とオンラインページを扱う |
| 個別名と関係は確認できたが外部IDなし | 内部IDで登録し、名前から内部ページ・登録済みの関連曲を開けるようにする。画像は未取得表示 |
| 結合表示だけで個別の人物を確認できない | 元の表示を保持し、未解決として扱う。記号で人物を確定分割しない |
| 別メニューにだけアーティストIDがある | 実ページ名を持つ独立した移動先として扱い、結合名の一部へ自動で割り当てない |

対象曲では、クレジットの演奏欄から `翟锦彦` と `8082Audio` を個別の名前として取得する材料がある。
この曲について両名を曲のArtistに採用する案は検討できるが、「すべての曲で演奏欄の全員をArtistへ昇格する」という一般ルールはまだ根拠が不足する。
役割を保持し、作詞・作曲や提供者を無条件に混ぜない条件が必要。

実装上は既存の内部アーティスト画面を利用できる。オンラインIDのないオンライン曲の人物を、フォルダ音源の意味の `isLocal=true` に変更する必要はない。
内部人物IDとオンラインIDを区別して、外部IDがない場合はオンライン取得を行わず内部表示から始める設計が候補となる。

別アルバムの同名を無条件に同一人物へ統合したり、結合表示を既知ページの名前で上書きしたりしない。
最低限「曲で受け取った表示」「個別のアーティスト関係」「移動先ID」「取得根拠」を区別することを勧める。
