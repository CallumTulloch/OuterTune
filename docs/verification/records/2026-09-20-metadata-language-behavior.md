# 名称の確定表示とアルバム全曲確認

2026-09-20。ユーザーの `metadata-language-behavior-proposal.md` に取り組む依頼と、英語表記関連資料も確認する追加依頼に基づく作業記録。

## 現象・期待する動作

- Nevermind の通常アルバム曲目には音源と異なる動画IDがあり、従来の曲カード経路だけでは13曲中10曲の原題確認が残る。
- 原題の候補と評価を別々に公開するため、再取得や別作品の追加で確定済み英語名が一時的に日本語へ戻り得る。
- 提案の表示表を今回の実装の基準にする。初回はコンテンツ言語、確認後の一度の切替を許容する。再取得・失敗中は最後の確定結果を保持し、完成した変更・不明・競合・撤回は反映する。
- 手動名・ローカルタグ・raw名称・再生ID・曲順・人物との関係・キュー・再生位置は保護する。

## 根拠・設計

- 開始時HEADは `7e48d375`。前回の未コミット実装・記録を保持して作業する。開始時の追跡差分とrepositoryファイルは無視対象 `build/diagnostics/metadata-language-behavior-20260920/baseline/` に保全。
- 前回の匿名応答では同一canonical playlistの13項目が `playlistSetVideoId` で対応した。名前・位置によるID統合には使わない。対応の証拠と直接原題の証拠と言語評価を別々に扱う。
- 表示用には完成した判定とその英語候補を保存する。処理中の候補変更と前の判定を組み合わせない。設定OFF・コンテンツ言語変更は保存された判断と現在の設定言語候補から直ちに選び直す。
- 一部取得・通信失敗・古い要求の遅着はアルバム全体の完了としない。

## 検証計画・状況

単体・DB/非同期テスト、debugでの実通信、release保存データの画面確認を別々に実施する。主要な実装とfixture境界の確認は完了したが、別作品の実通信結果と最終release APKはこの記録の末尾へ追記する。ここまでの合格を提案の全条件合格とは扱わない。

作品の期待値、初回/再訪/再起動、再評価待ち/失敗/撤回、設定切替、検索/通常アルバム/ライブラリ/プレイヤーの時系列を確認対象とする。既知のrelease証明書制約を再調査しない。

### release画面（保存データ）

エミュレータ上のreleaseを通常のバックアップ画面から保全したうえで、debug実通信後の整合したDBと設定を通常の復元画面から読み込んだ。Wi-Fi/データ通信を切った状態で、通常アルバムの全13曲、ライブラリ、ローカル検索（Smells）、プレイヤーが共通の確定名を使うことを確認した。元の曲への参照は上記DBとdebug画面のID表示で照合した。

設定OFFでは保存されたコンテンツ言語の名称へ戻り、ONで英語原題へ戻る。OFFで全曲が日本語になることは期待しない。今回、日本語要求の詳細候補にも`Lithium (Official Music Video)`、`Stay Away (Audio)`等が含まれ、これらは提供された設定言語候補をそのまま使っている。ONでは原題と一致する`Lithium`、`Stay Away`を採用した。

完全終了後の起動を15秒録画し、毎秒4フレームを抽出して確認した範囲では、ミニプレイヤーは初めの表示からPolly/Nirvanaであり、日本語を挟まなかった。再訪した通常アルバムも英語から開始した。これは保存済みデータでの観察であり、初回実通信や全画面の全フレーム検証とは区別する。オフラインの追加情報欄のエラーは名称確認の失敗ではない。既知のrelease TLS制約については再調査していない。

診断ログ・DB・録画・画面XMLは無視対象`build/diagnostics/metadata-language-behavior-20260920/`に保存する。

## 関連資料の照合と今回維持する条件

指定の提案に加え、[現行の仕様整理](../../metadata-language-spec.md)、[9/7の調査・ユーザー確認](2026-09-07-metadata-language-investigation.md)、[9/12の名称選択再点検](2026-09-12-metadata-language-review.md)、[コンテンツ言語の網羅記録](2026-09-12-content-locale-coverage.md)、[放置・再取得時の人物名問題](2026-09-12-artist-idle-refresh.md)、[9/19のアルバム曲名問題](2026-09-19-album-song-name-language.md)、[9/20の中断時記録](2026-09-20-metadata-language-review.md)を照合した。[人物表示仕様](../../artist-display-spec-draft.md)、[手動紐付け後の統合表示](2026-09-13-canonical-linked-artists.md)、[UI条件名の英語表記](2026-09-12-navigation-filter-labels.md)、[再生継続の検証](2026-09-12-playback-recovery.md)も関連境界として確認した。

- 英語とコンテンツ言語は設定ON/OFFにかかわらず取得・保持・検索する。名称の種類と安定IDを単位に選択し、初期OFF、ONは根拠のある英語原表記だけを採用する。日本の作品の正式英語題名も対象とする。原言語の証拠と要求言語は別であり、国籍・歌唱言語・Latin文字・英語候補との一致だけでは英語認定しない。
- 9/7後半の国・地域分類、未確認時の英語優先、固定Nirvana 3名称は途中案・旧実装。同記録冒頭の動的判定と後日の修正を優先する。9/7の設定言語欠損時の英語fallback案も、9/12の「未確認英語で元表示を上書きしない」に置き換わっている。
- 手動名、端末内の曲・アルバムタグを保護する。明示的にオンライン人物へ紐付けたローカル人物だけは既存のオンライン表示規則へ従う。言語変更で紐付けや人物の同一性を作り直さない。日本語UIの7条件チップを英語にする既存の別仕様は変更しない。
- 設定言語の正式な詳細名を、後着の弱い一覧名で更新しない。取得元の強さと観測時刻を組として扱う。英語原題と完全一致する取得済み別名は、動画付記のある詳細名より採用できるが、文字列の切り取りや未取得名の生成はしない。
- 原題未確認、評価待ち、評価完了後のUNKNOWN/OTHER/競合、通信失敗、正常応答による証拠撤回を分ける。保存済み確定表示は評価待ち・失敗中に保持し、完成した変更・撤回は反映する。設定変更は現在の候補と確定判定から即時に選択する。
- 既存の全DB入力指紋は、別作品の追加でも旧評価を一時失効させることがある。確定表示と処理中候補を分離することが今回の要件であり、特定の取得方法・閾値・待機時間をユーザーの必須仕様にしない。
- 前回の実機DB由来13曲では曲カード参照の成立が3曲、残り10曲はEMPTY。匿名の別動画ID13曲や、設定言語候補自体が英語の曲を使って全13曲改善と数えない。実機操作は再開せず、採取済みDBコピーとエミュレータで確認する。
