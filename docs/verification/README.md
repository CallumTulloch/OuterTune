# 検証記録

改修ごとの「何を確認し、何が未確認か」を短時間で復元するための索引です。
詳細な手順は [実装・検証の共通方針](../development-workflow.md)、未完了項目は
[後回し確認の台帳](pending.md) を参照してください。

## 状態の定義

| 状態 | 意味 |
| --- | --- |
| `PASS` | 記載した最終ソースまたは成果物で実行し、合格した |
| `OBSERVED` | 開発途中の版では確認したが、記載した最終版では未確認 |
| `FAIL` | 実行したが失敗した。既知問題でも結果を隠さない |
| `SKIPPED` | テスト側の `@Ignore` などにより実行されなかった |
| `DEFERRED` | 意図的に後回しにし、`pending.md` で追跡している |
| `BLOCKED` | 端末・認証・外部サービスなどがなく、現在は実行不能 |
| `N/A` | 変更範囲に関係しない |

`PASS` は「Gradle のタスクが成功した」だけで判断せず、テスト件数、fail、skip を確認します。
途中版での手動確認を、最終 commit の `PASS` として扱いません。

## 新しい記録の作り方

1. [`TEMPLATE.md`](TEMPLATE.md) を `records/YYYY-MM-DD-<短い改修名>.md` へコピーする。
2. 実装前に目的、範囲、合格条件、想定する確認を記載する。
3. 実行後にコマンド、対象、件数、時間、状態を記載する。
4. 後回し項目には `PM-007` のような重複しない ID を付け、[`pending.md`](pending.md) にも追加する。
5. この索引に一行追加し、commit 本文へ `Verification: <path>` を付ける。

記録には要約を残し、巨大な Gradle ログ、テストレポート、APK 自体はコミットしません。
