## 合意済みの基本仕様

| 項目 | 期待する動作 |
| --- | --- |
| 対象 | オンラインの曲名・アルバム名・人物名を、種類と安定IDごとに扱う。 |
| 二言語の取得・保持 | 英語を常に取得・保持対象にし、コンテンツ言語が英語以外ならその言語も取得・保持する。表示設定のON/OFFで取得対象を変えない。 |
| OFF（初期値） | 設定されたコンテンツ言語の名前を優先する。 |
| ON | 「正式な原表記が英語なら英語を利用」。英語の原表記と判断できる名前は英語、それ以外はコンテンツ言語を使う。 |
| 判定対象 | 一曲が英語であるだけで、人物名・アルバム名・別の収録曲を一括して英語と認定しない。 |
| 判定材料 | 国籍・歌唱言語・Latin文字であることだけでは決めない。日本の作品でも正式な英語タイトルは英語として扱う。 |
| 短い名称 | 単独で判断しにくい場合は、確かな対応がある同一アルバムの原題群を補助材料にする。 |
| 検索 | ON/OFFにかかわらず英語とコンテンツ言語の情報を検索対象にする。表示に選ばれなかった名称も保持する。 |
| 共通表示 | 同じ種類・IDの取得済み名称は共通の選択結果を使う。検索・アルバム・ライブラリ・プレイヤーごとに別の英語優先規則を設けない。 |
| 元データ | 表示の切替でraw名称・クレジット・曲や人物のID・関連・再生URIを書き換えない。再生位置やキュー順も維持する。 |
| ローカル・手動 | 端末内の曲・アルバムのタグや手動改名を自動の言語選択で上書きしない。アーティスト紐付けによる表示投影は別機能として扱う。 |

「英語名が取得できた」と「正式な原表記が英語と判断できた」は別の状態。
ONは、英語候補が存在するものを無条件に英語へ変える設定ではない。

### UI言語とコンテンツ言語

- アプリのUI言語は、操作ラベルやメッセージの言語を決める。
- コンテンツ言語・地域は、名前を取得する要求と表示名の選択に使う。
- コンテンツの明示設定を優先し、「端末に従う」は実際の端末システム言語・地域を参照する。
- アプリUI言語だけの変更ではコンテンツ言語を変えない。端末変更は「端末に従う」場合に反映する。

### 未取得・失敗・競合時

- 設定言語の名前が未取得なら、英語候補だけで各画面の元表記を上書きせず、その項目が持つ表記を維持する。
- 配信元が指定言語でも英語を返す場合や通信失敗時に、日本語名を作ったり翻訳したりしない。
- 原表記の判断が不明・競合なら、裏付けのある英語として採用しない。空応答や失敗で既存名を消さない。
- 共通の表示名がまだ選べない段階では、同じIDでも各応答の元表記が異なる可能性がある。取得完了後の共通表示と区別する。

## 現行実装の詳細・制約

以下は実装の説明であり、取得方法や待機時間を固定するユーザー要件ではない。

1. `ContentLocaleRepository`がコンテンツ言語・地域と変更通知を一元化する。要求開始時の言語を後続ページにも保持し、古い言語・認証条件の応答を現在の表示へ混入させない。
2. `MetadataNameRepository`がAPI観測・詳細補完から名称を収集する。`metadata_name`は種類・ID・言語・名称・取得元を分け、`metadata_fetch`に取得状態を記録する。
3. 表示は手動名を優先し、詳細候補と一覧等の候補を取得元の優先度・観測時刻で選ぶ。`MetadataNames.resolve`を曲・アルバム・人物の共通表示拡張が参照する。
4. 曲の原題補完は、英語の詳細応答で同じ動画IDの`MUSIC_VIDEO_TYPE_ATV`（Art Track）を確認して始める。現在、その詳細補完はMusicの`getQueue`に依存する。
5. 確認した英語SongItemとYouTube Mainの原情報を照合する。英語SongItemを保持していなければ原題取得時にも`getQueue`を使う。検索・アルバム応答に英語名があるだけでは、この経路が完了したことにならない。
6. 曲の原題は同じ動画IDに結び付ける。人物・アルバムの原表記は構造化された自動生成説明と既知のMusicクレジット・IDとの一致から扱い、文字列の区切りから人物IDを作らない。
7. 原題候補は`und`として保存し、原情報と自動言語評価を分離する。対象ID・原題・参照動画・方法・確度・入力指紋・評価時刻・versionを保持する。
8. 現判定器は`langid-java`を使う自動推定。元表記と小文字化の双方を評価し、個別判定は0.90以上、アルバム文脈は異なる曲IDの原題3件以上・0.95以上が条件。明確な非英語や競合を含む文脈は曖昧な短題の英語化に使わない。
9. 表示採用には、その対象の英語候補と原題評価の名称が整合することも必要。自動ENGLISH評価は人による確認済み根拠と同一ではない。旧形式や対象違いの評価を流用しない。
10. 自動の全曲原題補完は、ブックマーク・ライブラリ登録曲・ダウンロード対象曲を持つ保存アルバムに限定する。検索やキューの仮アルバムから無制限に全曲展開しない。通常の名前補完とアルバムを開いた際の取得は別に行う。
11. 再試行間隔は現在、SUCCESSが7日、EMPTYが24時間、FAILED等が5分。設定・認証条件や判定器versionによる再評価・再取得もある。24時間待機は仕様上の要求ではなく、現行の取得制御である。

## 未解決事項と確認範囲

- ATV確認経路の変更、代替取得、EMPTYの再試行方針、別版への原題根拠の共有は未決定。実装制約を解消する際にも、同名だけでIDを統合したり英語候補を原題と認定したりしない。
- 自動言語推定は万能ではなく、英語中心のアルバムに混ざる曖昧な短題などには限界がある。モデル条件の変更は基本仕様との整合と回帰例で判断する。
